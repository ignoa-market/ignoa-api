# 모니터링 가이드

운영 서비스(ignoa-api, ignoa-payment)를 어떤 화면과 알림으로 지켜보는지 정리한 문서.
이 폴더의 JSON·YAML은 Grafana Cloud(`ignoa.grafana.net`)에 적용된 설정의 기록이다.

## 무엇이 있나

### 대시보드

| 대시보드 | 답하는 질문 | 주요 내용 |
|---|---|---|
| `ignoa / 개요` | 서비스가 정상인가? | api·payment 수집 상태(UP/DOWN), 요청 수, 5xx 비율, 응답 시간 |
| `ignoa-api / 자원` | 무엇이 부족한가? | CPU·Heap·GC, DB 커넥션, Tomcat 스레드, 분산 락 |

### 알림 (Slack `#ignoa-alert`)

| 알림 | 언제 오나 | 심각도 |
|---|---|---|
| `TargetDown` | 서버 지표가 2분 이상 수집되지 않음 | critical |
| `HighErrorRate` | 5xx 비율이 5분 이상 5% 초과 | warning |

## 왜 이 기준인가

- `TargetDown`은 서버가 통째로 멈춰 지표가 사라진 경우도 장애로 본다. 서버가 멈추면 값이 0이 아니라 아예 없어지기 때문이다.
- `HighErrorRate`는 최근 5분 요청이 10건 미만이면 판단하지 않는다. 요청 1건 중 1건 실패를 100%로 보는 오탐을 막기 위해서다.
- 알림은 서버별로 따로 온다. 한 서버의 알림이 다른 서버 알림에 묶여 늦게 오지 않게 하기 위해서다.

## 알림이 오면

1. 개요 대시보드에서 어느 서버의 어떤 지표가 이상한지 확인한다.
2. 자원 대시보드에서 부족한 자원을 확인한다.
3. 에러라면 Sentry 이벤트의 `trace_id` 태그로 Tempo(요청 흐름)와 Loki(앞뒤 로그)를 조회한다.
